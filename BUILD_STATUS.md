## Stage C Step 1: Official PayPal "Provide Evidence" Request Contract

**RESOLVED DISCREPANCY:** The cURL examples in PayPal docs use `-H 'Content-Type: multipart/related'` with `-F` flags (which is curl's multipart/form-data mechanism). The PayPal API reference spec lists the content type as **`multipart/form-data`**. The critical requirement is that the `input` JSON part MUST have explicit `Content-Type: application/json` set on the Blob/part. Our implementation uses `new FormData()` with `new Blob([inputJson], { type: 'application/json' })`, which is correct.

From official PayPal Disputes API (v1) documentation:

- **Endpoint:** `POST https://api-m.sandbox.paypal.com/v1/customer/disputes/{dispute_id}/provide-evidence`
- **Method:** `POST`
- **Headers:**
  - `Authorization: Bearer <ACCESS_TOKEN>`
  - `Content-Type: multipart/form-data; boundary=<BOUNDARY>` (auto-generated by FormData/fetch)
- **Multipart Form Parts:**
  1. **`input` (Application/JSON part):**
     - The `input` part MUST have `Content-Type: application/json` explicitly set.
     ```json
     {
       "evidences": [
         {
           "evidence_type": "PROOF_OF_FULFILLMENT",
           "evidence_info": {
             "tracking_info": [
               {
                 "carrier_name": "FEDEX",
                 "tracking_number": "TRK-10025",
                 "tracking_url": "https://..."
               }
             ]
           },
           "notes": "Order ORD-1024 shipped via FedEx Ground with tracking TRK-10025. Shipment status: In transit."
         }
       ]
     }
     ```
     - `evidence_type`: `PROOF_OF_FULFILLMENT` | `PROOF_OF_REFUND` | `PROOF_OF_SHIPMENT` | `OTHER`
     - `tracking_info`: array of tracking objects (supported for `PROOF_OF_FULFILLMENT`):
       - `carrier_name`: Required enum (`FEDEX`, `UPS`, `USPS`, `DHL`, `OTHER`, etc., length 1–255)
       - `carrier_name_other`: String (1–2000 chars, **mandatory if `carrier_name` is `OTHER`**)
       - `tracking_number`: String (1–255 chars)
       - `tracking_url`: Optional valid URL
     - `notes`: String (1–2000 chars). **Rule: Must NOT claim delivery or guarantee outcomes.**
  2. **`file1`, `file2`, ... (Binary file parts):**
     - Parameter name: `file1`, `file2`, etc.
     - Content-Type: Mime type of the file (`application/pdf`, `image/jpeg`, `image/png`, `image/gif`)
     - Filename: Original filename
     - Content: Binary file bytes
- **Payload Constraints:**
  - File types: `.pdf`, `.jpg`, `.jpeg`, `.gif`, `.png`
  - Per-file limit: Less than 10 MB per file
  - Total payload limit: Up to 50 MB per API call

### Carrier Mapping (from PayPal API reference)
- `carrier_name` is an enum. Known values include: `FEDEX`, `UPS`, `USPS`, `DHL`, `DPD`, `TNT`, `ROYAL_MAIL`, `CANADA_POST`, `AUSTRALIA_POST`, `ARAMEX`, etc.
- When the carrier is NOT in the enum, set `carrier_name: "OTHER"` and provide the actual name in `carrier_name_other` (1–2000 chars, mandatory when `carrier_name` is `OTHER`).
- Smart mapping: `FEDEX_GROUND` → `FEDEX`, `UPS_GROUND` → `UPS`, etc.
